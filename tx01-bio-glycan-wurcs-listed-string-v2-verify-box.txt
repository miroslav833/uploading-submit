The compound is a model nonasaccharide that is not registered in GlyTouCan, so no repository page shows this string. The key was obtained in two ways, both in the attached notes: the repository's own format converter, given the compound in IUPAC condensed form written in two different orders, returns this string with the message that no accession exists; and a short program that builds the string from the residue tree gives the same and also reproduces six registered strings.

By hand. Tree: reducing GlcNAc R5 with Fuc R2 on O3, Gal R8 on O4 and Man R6 on O6; R8 with Fuc R7 on O2, GlcNAc R3 on O3 and Neu5Ac R4 on O6; Man R9 on O4 of R3; Gal R1 on O2 of R6. Residue codes: GlcNAc a2122h-1b_1-5_2*NCC/3=O, Fuc a1221m-1a_1-5, Gal a2112h-1b_1-5, Man a1122h-1a_1-5, Neu5Ac Aad21122h-2a_2-6_5*NCC/3=O. Lettering from the reducing end, depth first, lower attachment position first: a R5, b R2, c R8, d R7, e R3, f R9, g R4, h R6, i R1. Unique residues by first appearance give the sequence 1-2-3-2-1-4-5-4-3, and the linkages sorted by parent are a3-b1_a4-c1_a6-h1_c2-d1_c3-e1_c6-g2_e4-f1_h2-i1.

A natural wrong answer letters the larger branch first (Gal on O4 before Fuc on O3). It has the sequence 1-2-1-3-4-5-3-2-4 and the linkages a3-i1_a4-b1_a6-g1_b2-e1_b3-c1_b6-f2_c4-d1_g2-h1. It describes the same compound but is not the normalised string.

Check (Python, standard library): the program key.py in the notes; its core is a depth-first walk
def walk(t, parent=None, pos=None):
    me = len(order); order.append(t[0])
    if parent is not None: links.append((parent, pos, me, anomeric(t[0])))
    for p, s in sorted(t[1], key=lambda ps: ps[0]): walk(s, me, p)
followed by numbering the residue codes by first appearance and sorting the linkages.
